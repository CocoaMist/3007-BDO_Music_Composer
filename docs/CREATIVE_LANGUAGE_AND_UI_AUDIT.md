# 创作语言与界面审计

状态：当前产品契约。适用于首页、工作区、钢琴卷帘、转录、检查、设置和发布相关界面。

## 创作语言：静谧乐谱工坊

BDO Music Composer 不是通用办公软件，也不应模仿游戏商城。它的界面语言是“静谧乐谱工坊”：深色环境负责让音乐内容浮现，温暖金色标记用户即将确认的创作动作，轨道颜色承载乐器身份，青色承载参考与证据。装饰必须让位于谱面、波形、音符和可解释的诊断。

“守正”是遵守桌面软件的可预测性、可访问性、撤销边界、数据安全和领域语义；“出奇”是把 BDO 乐理、奏法、容量、转录证据和游戏导出约束变成创作反馈，而不是增加炫技动画或隐藏自动化。

## 十条可执行原则

1. **内容高于外壳。** 音符、轨道、波形和问题证据拥有最高视觉优先级；大面积材质层只用于建立空间，不与内容竞争。
2. **金色只表示承诺。** 主操作、播放头、当前选择可使用暖金色；不可把金色当作普通装饰或同时强调多个动作。
3. **轨道色是数据身份。** 同一轨道在时间线、钢琴卷帘、列表和诊断中保持同一颜色，不用状态色覆盖身份色。
4. **青色表示参考与证据。** 参考音频、转录候选、比对结果和辅助信息使用青色系；它们不能伪装成已经提交的编辑。
5. **状态色含义固定。** 绿色表示已验证或可交付，琥珀色表示需要复核，红色表示阻断或破坏性风险。
6. **一个概念只有一个名称和一个所有者。** BPM 由全局 BPM 控件表达；参考音频是参考泳道，不计为音乐轨道；界面不能用两个相邻控件重复同一事实。
7. **渐进披露。** 常用动作始终可见，专家参数按模式或任务展开；模式切换不能让控件高度跳动或打断肌肉记忆。
8. **辅助创作必须可解释。** 本地分析和 AI 流程遵循“证据 → 建议 → 预览 → 用户接受”，不得静默修改当前 `TrackState`。
9. **每个上下文只有一个主操作。** 其他操作按导航、编辑、验证、发布分组；关闭和取消不与提交争抢视觉权重。
10. **安静页面与密集编辑器共享同一语义。** 首页和设置允许留白，时间线和卷帘允许高密度，但仍共享间距、状态色、焦点、菜单和键盘规则。

## 界面逐项评估

| 界面 | 当前判断 | 不合理之处 | 本轮与后续动作 |
|---|---|---|---|
| 首页 | 视觉辨识度强，快速入口清楚 | 资料库必须与左侧工作柱形成完整基线；“最近项目/项目”存在轻微命名重复 | 资料库纵向填满并保留滚动，避免悬空截断；后续统一页签与卡片标题的名词层级 |
| 全局工具栏 | 项目、播放、设置、转换边界基本清楚 | 时间线摘要再次显示相邻 BPM 控件已经表达的数值 | 本轮摘要只保留轨道数与拍号 |
| 时间线 | 可见范围索引和轨道身份表达成熟 | 参考音频泳道被计入“轨道”标题，导致真实轨道数与顶部摘要不一致 | 本轮区分布局行数和音乐轨道数 |
| 钢琴卷帘 | 编辑、力度、奏法、参考轨具备专业工作流 | 英文等长文本下“其他轨”会被固定宽度裁切；第二行控件密度偏高 | 本轮按字体测量自适应；后续基于任务频率重排第二行，而非继续缩小字号 |
| 转录工作区 | 已有置信度、候选、参考音频和提交边界 | 空数据状态难以表达下一步；专业参数与创作建议仍需更稳定的叙事顺序 | 后续统一为“来源—证据—建议—提交”四段式，并维持本地优先与显式接受 |
| 转换检查 | 摘要卡、报告和问题列表层级正确 | 无问题时列表留下大块空白；底部工具和关闭按钮权重接近 | 后续增加真正的完成态，并将复制/对比/覆盖率归入工具组 |
| 优化与乐理诊断 | 已具备确定性、游戏安全和解释基础 | 技术诊断容易压过音乐意图 | 后续按“音乐目标、游戏约束、变化预览”呈现，默认不展示内部算法术语 |
| 设置 | 导航、表单列和分区稳定，接近专业桌面软件 | 路径行的选择/打开外观相似，长页面仍偏配置清单 | 后续为路径动作建立图标语义，并把高风险/少用选项移到高级区 |
| 更新、恢复与支持 | 信任边界和恢复链已专业化 | 平时不应占据创作主流程 | 维持后台能力，仅在有证据或明确用户操作时出现 |
| 多人同步 | 全局 BPM 权威与适配边界清楚 | 网络房间尚不是当前核心能力 | 保持适配器边界，不为未来能力提前增加主界面噪声 |

## 本轮设计判定

- 首页的艺术感保留，资料库与左侧工作柱共同延伸到底部，形成稳定的桌面工作区基线。
- 顶部 BPM 只出现一次；摘要负责结构，控件负责修改。
- 参考音频继续占用一条可滚动的视觉行，但不会伪装成工程轨道。
- 本地化控件宽度以实际字体测量为依据，不再假设中文短标签能够代表所有语言。
- 没有新增每个菜单自己的样式；弹出菜单继续由应用级语义主题统一管理。

## 下一阶段门槛

后续界面调整只有在满足以下条件时才可合入：支持的五种语言在最小窗口尺寸下无裁切；键盘焦点和辅助名称完整；主操作唯一；状态色不跨语义复用；参考或推断结果必须与已提交内容可区分；离屏布局烟雾测试、目录测试和全量单元测试通过。

## 音符创作工作区

音符编辑器采用工作区式布局：左侧工具轨承载选择、绘制、擦除、切分和视图适应；中央钢琴卷帘保持内容优先；底部浅层属性条承载音符、奏法、网格和音阶高亮，不使用会持续挤压画布的右侧检查器。顶部只保留传输、撤销/重做、量化、力度、参考轨和播放头跟随。

该布局不会改变编辑事务。画布继续编辑独立草稿，撤销、自动恢复和试听读取草稿；只有“应用”才通过主窗口提交到正式 `TrackState`，关闭则丢弃草稿并清除恢复覆盖层。擦除、切分、力度与奏法操作均必须进入同一撤销栈，不能直接绕过提交边界修改正式轨道。
