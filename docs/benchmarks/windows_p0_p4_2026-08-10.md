# Windows P0–P4 性能与架构落实证据

状态：**已实现并完成本机自动化验证（2026-08-10）**。

本轮只面向 Windows x64，不承诺跨平台行为。目标不是把项目机械地改写成
C++，而是在保持编辑、预览和导出语义的前提下，把可测量的交互延迟、刷新
边界、原生音频能力与扩展协议收口。本文数字是当前机器上的工程证据，不是对
所有 Windows 设备的认证。

## P0：交互性能资格门

新增可选的 Qt 交互探针，记录输入到下一次绘制的延迟、16 ms 心跳和主线程
停顿。探针默认关闭，仅在 `BDO_UI_PERF_DIAGNOSTICS=1` 或资格工具中启用，
不会改变普通启动路径。

Windows 11 / AMD64 / Qt offscreen 资格结果：

| Qt 缩放 | 窗口构造 | 首帧 | 输入到绘制 P95 | 停顿数 |
|---:|---:|---:|---:|---:|
| 100% | 196.71 ms | 40.26 ms | 1.70 ms | 0 |
| 150% | 202.67 ms | 44.82 ms | 1.87 ms | 0 |
| 200% | 196.95 ms | 50.58 ms | 3.09 ms | 0 |

资格门为：构造 `< 1500 ms`、首帧 `< 500 ms`、输入到绘制 P95
`< 16.7 ms`、交互窗口停顿为 0。结构压测中的同步绘制循环会主动占用事件
循环，因此其心跳停顿只表示“基准正在压测”，不计入日常交互资格结论。

密集画布（120 轨 / 48,000 音符；12,000 正式音符 + 8,000 参考音符）：

- 时间线 paint P95：1.48 ms；
- 钢琴卷帘 paint P95：5.15 ms；
- 窗口构造：239.98 ms；首帧：58.80 ms。

## P1：Windows 绘制与刷新减负

- 时间线和钢琴卷帘声明为不透明绘制表面，避免 Windows 背景擦除和重复合成；
- 工作区刷新执行器识别已经由轨道、网格或增量更新触发的失效，不再追加一次
  无意义的全量 `timeline.update()`；
- 可见范围索引与批量绘制边界保持不变，没有用隐藏图层或减少正确数据换取数字。

## P2：主窗口职责收口

工作区刷新计划的 Qt 执行逻辑已从主窗口抽到
`ui/workspace_refresh_qt.py`。主窗口只保留薄委托；领域刷新计划仍由 Qt-free
控制器拥有。这样后续可独立剖析和替换刷新策略，而不会继续扩大主窗口。

## P3：原生音频语义扩展与门禁

Windows C++ 核心新增完整的 1–28 预览发音包络、主总线余量控制和软限制器，
并由 Python/C++ 差分测试锁定。相同 176 声部、32 样本、256 frame 负载：

| 路径 | 条件 | P95 | P99 | P99/块预算 | 最大值 |
|---|---|---:|---:|---:|---:|
| Python | 36 kHz，全 Reverb/Delay/Chorus | 5.99 ms | 7.38 ms | 103.8% | 14.49 ms |
| 原生 | 48 kHz，发音包络 + 主限制器 | 0.35 ms | 0.51 ms | 9.5% | 1.08 ms |

两行尚不是完全同语义对照：原生路径仍未实现 Reverb/Delay/Chorus 效果总线。
因此它继续对任何非零效果发送**明确拒绝并安全回退**，不会静默丢弃效果，也
尚未获准替代生产混音器。这是本轮最重要的正确性门禁。

## P4：面向未来的扩展边界

- 共享层新增版本化主机契约与能力协商；API 身份、版本、传输方式或能力不匹配
  时一律失败关闭；
- 新增有界 UTF-8 NDJSON 信封，限制为 1 MiB、精确字段、有限数值；
- 优化器插件在执行前完成能力协商，拒绝未知或重复能力；
- SDK 暴露同一套协商入口；当前可信进程内插件不被误称为沙箱，未来非可信扩展
  预留独立进程协议。

## 验证边界

已覆盖性能记录器、工作区刷新、画布绘制、优化器/SDK 协商、NDJSON 协议、
原生生命周期、seek、全部 28 种发音包络与主限制器差分测试。完整测试套件和
仓库卫生结果见本轮交付记录。

尚未宣称完成的外部资格项：真实音频设备 30 分钟零 XRUN、低端集显、4K 原生

不能由 offscreen 或离线基准代替。
